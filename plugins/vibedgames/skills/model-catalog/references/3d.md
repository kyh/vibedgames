# 3D: Models, Rigs and Animation

One path per job. Take it unless it fails; the alternatives at the bottom are for when it does.

| Job                                        | Endpoint                                                     | MCP tool              |
| ------------------------------------------ | ------------------------------------------------------------ | --------------------- |
| Prop or character from a prompt            | `meshy/v7.1/text-to-3d`                                      | `generate_3d`         |
| Prop or character from an image            | `meshy/v7.1/image-to-3d`                                     | `generate_3d`         |
| From one to four views of the same subject | `meshy/v7.1/multi-image-to-3d`                               | `generate`            |
| Rig a humanoid and bake animation clips    | `meshy/rigging/multi-animation`                              | `generate_animate_3d` |
| Prop that hinges, opens or breaks, as code | none: the `image-to-threejs` skill                           | —                     |
| Load, normalize and play it in Three.js    | none: the `threejs` skill's `references/generated-assets.md` | —                     |

3D jobs take 1–5 minutes: always `--async`, then `vg generate status`. Verify an endpoint with `vg generate schema <id> --json` and price it with `vg generate pricing <id> --json` before a batch.

## A mesh

```bash
REQ=$(vg generate run meshy/v7.1/text-to-3d \
  --prompt "a stylised wooden treasure chest, game asset" \
  --target_polycount 8000 --async --field request_id)

vg generate status meshy/v7.1/text-to-3d "$REQ" --download "./public/models/chest/" --json
```

- The GLB is `model_glb`; `thumbnail` is a preview. A directory as `--download` keeps every file under its own name.
- `target_polycount` sets the budget: 5k–15k for a prop, 15k–40k for a hero character, the default 30k otherwise.
- From an image, pass `--image_url` (from `vg generate upload`) instead of `--prompt`. Cut a busy background out first (`bria/guided-remove-background`): the mesh comes from the silhouette.
- `enable_pbr` adds metallic, roughness and normal maps; `topology quad` for smooth surfaces, the default `triangle` for detail.
- Single objects reconstruct well; scenes don't. "A medieval sword with an ornate handle" works, "a knight in a forest" doesn't.

## A character that will animate

Rigging quality is decided when the image is made, before any 3D step:

- **Full-body A- or T-pose**, front-facing, arms clear of the body, legs apart, symmetric, head to feet in frame.
- **No props, capes, tabards or long skirts fused into the silhouette**: they merge limbs into the body and confuse the auto-rigger. Give weapons to the character afterwards as separate meshes.
- **Check the image shows the pose** before paying for 3D. Models drift toward action poses; regenerate with a stronger pose instruction rather than rigging a bad one.
- **Hard-surface designs** (plate armour, mechs) rig worse than organic silhouettes: budget a retry.
- Only humanoids rig. A quadruped or a creature with no clear limbs is a static mesh, animated in code (bob, squash, procedural legs).

Then model it in that pose: `generate_3d` with `pose_mode: a-pose`, or `--pose_mode a-pose` on the CLI.

## Rig and animate

One call rigs the mesh and bakes every clip you name onto the same skeleton:

```bash
REQ=$(vg generate run meshy/rigging/multi-animation \
  --model_url "$CHARACTER_GLB_URL" \
  --animation_action_ids '[0, 613, 4, 178, 8]' \
  --async --field request_id)

vg generate status meshy/rigging/multi-animation "$REQ" --download "./public/models/knight/" --json
```

- `model_url` is any humanoid GLB: the `model_glb` URL `generate_3d` returned, or one from another model.
- Output: `rigged_character_glb` (the character on its skeleton), `animations[]` (one `animation_glb` per id, in request order) and `basic_animations` (`walking_glb`, `running_glb`, free with every rig).
- Every clip shares the skeleton, so load the character once and play each file's clip on one mixer (`threejs` → `generated-assets.md`, "One character, many clips").
- Ship one file: `vg asset merge-clips --model_url <rigged_character_glb> --clip_urls <each animation_glb, walking_glb, running_glb> --names idle,attack,walk,run --out public/models/hero.glb` copies every clip onto the rigged character (free, on vibedgames' servers), then `vg asset optimize` shrinks it. The `asset_merge_clips` and `asset_optimize` tools do the same over MCP.
- Ask for every clip the game needs in one call: up to 10, plus the free walk and run. A second call re-rigs, and its skeleton may not match the first, so budget a character to 10 clips.
- `height_meters` (default 1.7) sets the rig's scale; `skeleton_template` (`mixamo`, `ue5_mannequin`, `unity_humanoid`, …) matches a skeleton other assets already use.

## Fix a mesh before rigging or reuse

- **Remesh** a generated mesh to clean quads at a target polycount before
  rigging (a rig binds to the mesh it is given; ~20k triangles suits a hero):
  `tripo3d/tripo/remesh`. Keep the exact remeshed GLB beside its paid rig.
- **Retexture** an existing mesh from a prompt or reference image, for
  variants and palette passes without paying for new geometry:
  `meshy/v7/retexture` (there is no 7.1 retexture; this is the current one).

## Make it game-ready

`vg asset` runs on vibedgames' servers, free, with nothing to install; every
`--*_url` takes a URL generate returned or a local path, and `--out` saves
the result:

- `vg asset inspect --model_url hero.glb`: triangles, size in metres,
  textures, joints, clips. Check every generated mesh before placing it.
- `vg asset optimize --model_url car.glb --yaw_degrees -90 --size 4.5
  --origin feet --target_triangles 8000 --out public/models/car.glb`: face
  +z, scale, ground, simplify, meshopt-compress in one pass (`--up_axis z`
  for z-up files, `--strip_meshes` for a clip-only file).
- `vg asset merge-clips`: above, under Rig and animate.

FBX conversion and retargeting a clip onto a different skeleton are not
hosted yet.

Inspect each stage (mesh → remesh → rig → clips) in the running game before
paying for the next, and prove the route on two different bodies first.

## A move no clip covers

Only when the library has nothing close (a signature move, a cutscene beat): `fal-ai/hunyuan-motion` (or `/fast`) turns a prompt into an FBX clip on a 52-bone SMPL-H skeleton (root `Pelvis`, 30 fps, 0.5–12 s), with no mesh. It plays on nothing until retargeted: load it with `FBXLoader`, map each of the character's bones to its SMPL-H name by reading both skeletons with `traverse`, then bake it with `SkeletonUtils.retargetClip(characterMesh, clipMesh, clip, { names })` from `three/addons/utils/SkeletonUtils.js`. Expect a session of tuning; a library clip is minutes.

## Alternatives

When Meshy 7.1 fails on a subject, rejects it, or the style needs another model:

- `tripo3d/p2/text-to-3d`, `tripo3d/p2/image-to-3d`: Tripo P2, the strongest alternative
- `fal-ai/hunyuan-3d/v3.1/pro/text-to-3d`, `fal-ai/hunyuan-3d/v3.1/pro/image-to-3d`: Hunyuan 3D v3.1 Pro
- `fal-ai/hunyuan-3d/v3.1/rapid/image-to-3d`, `fal-ai/triposr`: fast drafts
- `fal-ai/hyper3d/rodin/v2`: Rodin v2, from an image

Their GLBs rig with the same `meshy/rigging/multi-animation` call. Older Meshy generation versions (v6, v7 text/image-to-3d) are superseded by 7.1: don't pick them. `meshy/v7/retexture` is the exception, above.
